# SMPLR — DAWless-сэмплер и секвенсор (PoC)

SMPLR — экспериментальный автономный сэмплер-секвенсор на ESP32-S3 с Akai MPK mini. Долгосрочная идея — небольшой аппаратный инструмент, который сэмплирует, секвенирует и обрабатывает звук без компьютера.

**Текущее состояние: ранний PoC, версия 0.0.1.1. Активная ветка разработки — `current-state`. Физического прототипа пока нет.** Поведение устройства проверяется в Wokwi и регрессионными тестами на ПК.

## Что работает сейчас

Текущий PoC умеет:

- загружаться в небольшой интерфейс с четырьмя разделами проекта;
- редактировать и проигрывать пошаговый паттерн на 4 дорожки: KICK, SNARE, HAT и PERC;
- 16 шагов четвертями — паттерн на 4 такта;
- запускать и останавливать транспорт, менять BPM во время воспроизведения;
- включать метроном;
- прослушивать четыре встроенных ваншота с клавиатуры;
- регулировать громкость каналов, метронома и мастера в микшере;
- экспортировать текущий паттерн в WAV: 44,1 кГц, 16 бит, моно;
- считать звук в отдельной задаче, независимо от интерфейса;
- вести часы транспорта во времени звуковых сэмплов, а не в цикле интерфейса;
- проверять систему ввода в Wokwi пэдами, клавишами и восемью симулированными энкодерами;
- прогонять детерминированные тесты звукового движка и тайминга транспорта на ПК.

Два раздела интерфейса — сознательно превью, а не готовые инструменты:

- **Piano Roll** хранит и показывает ноты, но звука они пока не дают.
- **Arrangement** показывает текущий паттерн в виде аранжировки на 16 тактов, но редактирования песни ещё нет.

## Чего ещё нет

PoC пока не умеет:

- принимать USB-MIDI с настоящего MPK;
- выводить звук через I2S-кодек;
- загружать пользовательские сэмплы с накопителя;
- записывать ноты вживую;
- записывать сэмплы со звукового входа;
- сохранять проект;
- работать с несколькими независимыми паттернами;
- обрабатывать звук эффектами;
- полноценный сценарий работы сэмплера.

Точный список текущих ограничений с доказательствами — в [`docs/known-issues.md`](docs/known-issues.md).

## Как попробовать

### В браузере

Текущая симуляция в Wokwi:

https://wokwi.com/projects/475304919575815169

Проект в браузере — симуляция устройства. Это не настоящий MPK, и звуковой тракт там не финальный вывод через кодек.

### Локальная сборка прошивки

Из корня репозитория:

```bash
arduino-cli compile -e firmware
```

Конфигурация целевой платы закреплена в [`firmware/sketch.yaml`](firmware/sketch.yaml).

### Регрессионные тесты

```bash
python tools/audio_bitexact_test.py
python tools/transport_timing_test.py
```

Тесты идут на ПК и не требуют ESP32.

### Дымовой тест на ПК

```bash
cd sound-engine
make test
```

Это лишь небольшой исторический тест сборки и звука. Настоящий звуковой движок прошивки — `firmware/audio_engine.*`.

## Архитектура

```text
                        INPUT
                          |
                          v
                    InputSource
                          |
                          v
                    firmware.ino
                    UI / control
                          |
                 control state + pattern
                          |
                +---------+---------+
                |                   |
                v                   v
          UiScreens             Transport
                                   |
                          musical clock
                          + pattern data
                                   |
                                   v
                              AudioEngine
                                   |
                                   v
                              AudioSource
                                   |
                                   v
                           audio output
                                   |
                        +----------+----------+
                        |                     |
                     Wokwi                 future
                    1-bit GPIO            I2S codec


offline export
     |
     v
PatternExporter -> AudioEngine -> WAV
```

Основные границы ответственности:

**`InputSource`** превращает физический или симулированный контроллер в события ввода. Остальное приложение не должно зависеть от сдвиговых регистров и GPIO.

**`firmware.ino`** — слой приложения. Он владеет верхнеуровневым состоянием интерфейса и направляет действия пользователя в остальные модули. В PoC это сознательно одна точка входа.

**`StepSequencer`** хранит данные паттерна. Музыкальными часами, интерфейсом и выводом звука он не владеет.

**`Transport`** владеет музыкальным временем, плейхедом, метрономом и превращает шаги паттерна в запуски голосов. Он же — `AudioSource` для живого вывода.

**`AudioEngine`** рендерит ваншоты, микширует, применяет усиление и ограничитель. Он не знает, куда уходит его выход — в Wokwi или в WAV-файл.

**`PatternExporter`** рендерит паттерн офлайн своим экземпляром `AudioEngine` и передаёт WAV через Serial Monitor в Wokwi.

**`OneBitAudioOutput`** — текущий адаптер вывода для Wokwi. Он сознательно отделён от звукового движка: на железе вывод планируется через I2S-кодек.

Подробнее — в [`docs/architecture.md`](docs/architecture.md).

## Что чем проверяется

Разные среды доказывают разное:

| Среда | Что проверяет сейчас |
| --- | --- |
| ПК | регрессию звука, тайминг транспорта, небольшие утилиты |
| Wokwi | загрузку, интерфейс, симулированный ввод, секвенсор, симулированный вывод и экспорт |
| Настоящий MPK | снятую раскладку MIDI для задокументированного пресета |
| Настоящее железо | **пока недоступно** |

Результат в Wokwi — не проверка на железе.

## Целевое железо

Планируется:

- ESP32-S3 N16R8;
- 16 МБ флеша;
- 8 МБ octal-PSRAM;
- дисплей ILI9341;
- microSD;
- внешний аудиокодек;
- Akai MPK mini по USB.

Конкретный кодек и ряд аппаратных ограничений производительности ещё не выбраны. См. [`docs/roadmap.md`](docs/roadmap.md) и [`docs/mpk-mapping.md`](docs/mpk-mapping.md).

## Как ведётся разработка

Проект разрабатывается с Claude Code как инструментом реализации и ревью.

За автором:

- требования к продукту;
- рамки проекта;
- архитектурные решения;
- критерии приёмки;
- наблюдения на железе;
- финальное ревью.

Репозиторий сознательно не скрывает помощь ИИ. Цель — воспроизводимый инженерный проект, а не попытка выдать сгенерированный код за непроверенную ручную работу.
