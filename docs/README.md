# Документация

Этот каталог описывает проект на нескольких уровнях. Начинайте с самого короткого полезного документа, а не читайте всё подряд.

| Файл | Назначение |
| --- | --- |
| [`../README.md`](../README.md) | Что за проект и как его запустить |
| [`architecture.md`](architecture.md) | Как устроено текущее выполнение |
| [`verification.md`](verification.md) | Что и где на самом деле проверено |
| [`known-issues.md`](known-issues.md) | Что ещё сломано, медленно или не проверено |
| [`mpk-mapping.md`](mpk-mapping.md) | Снятое поведение настоящего контроллера |
| [`hardware-bom.md`](hardware-bom.md) | Планируемое железо: что куплено, что докупить, что отклонено |
| [`backlog.md`](backlog.md) | Активная работа |
| [`roadmap.md`](roadmap.md) | Направление развития продукта |
| [`code-review-brief.md`](code-review-brief.md) | Бриф для будущего код-ревью в Claude Code |
| [`code-review-2026-09-19.md`](code-review-2026-09-19.md) | Последнее ревью кода и статус его находок |
| [`test-plan-2026-09-20.md`](test-plan-2026-09-20.md) | План проверки всего функционала: сценарии, оракулы, порядок |
| [`test-report-2026-09-20.md`](test-report-2026-09-20.md) | Что дало исполнение плана: результаты и находки |
| [`archive/`](archive/) | Исторические брифы и материалы планирования |

## Порядок чтения для нового разработчика

Для первого знакомства:

```text
README
  ↓
architecture
  ↓
verification
  ↓
known-issues
```

`mpk-mapping.md` — когда работаете с вводом с контроллера.

`hardware-bom.md` — когда работаете с выводом звука, питанием, USB-хостом или готовите сборку на железе.

`backlog.md` — когда берёте активную задачу.

`roadmap.md` — только когда нужен долгосрочный контекст продукта.

Файлы в `archive/` не используйте как текущие спецификации.
