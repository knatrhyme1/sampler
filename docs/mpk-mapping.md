# Раскладка Akai MPK mini mk3

Стори **3.2** из [`backlog.md`](backlog.md). В отличие от первой версии этого
файла, всё ниже снято живьём с реального контроллера через
[`tools/midi_logger.py`](../tools/midi_logger.py), а не предположено по общим
знаниям о MPK mini. Дата снятия: 2026-09-16.

**Важно:** на контроллере стоит кастомный пресет (PGM) с ремапингом под FL
Studio, а не заводской. Всё ниже снято именно с него. С заводским пресетом
контроллер может слать другие номера нот и CC, и тогда раскладка не
совпадёт. Если на контроллере переключить PGM-слот, номера тоже уедут —
перепрогонять `tools/midi_logger.py` заново, раздел
[Как переснять](#как-переснять) ниже.

**Другие MIDI-контроллеры не снимались и не проверялись** — ни другие модели
Akai, ни контроллеры других производителей.

## Метод

`tools/midi_logger.py` слушает MIDI-порт `MPK mini 3 1`, печатает каждое
входящее сообщение с типом, каналом, номером и значением. Порт открыт без
игнорирования timing/sysex-сообщений (`ignore_types(False, False, True)` в
backend rtmidi у `mido`), поэтому если бы контроллер слал MIDI-клок или sysex —
это было бы видно. Раскладка снята интерактивно: элементы контроллера жались
по одному под диктовку, попадание в лог сверялось по времени и по значению.

## Клавиши (25 шт)

- Канал **1**, ноты **48–72** (C3–C5), хроматически, по одной ноте на клавишу.
- Velocity динамическая, весь диапазон 0–127 подтверждён.

## Пэды (16 шт, банк A + банк B по 8)

- Канал **10** (стандартный ударный канал) у всех пэдов в обоих банках.
- Номера нот **не хроматические** — это диатоническая C-мажорная гамма,
  специфичная для текущей PGM. Нумерация ниже — по физической позиции (верхний
  ряд / нижний ряд, слева направо), а не по подписям на корпусе Akai.
- Velocity динамическая, весь диапазон 0–127 подтверждён (кроме случаев с
  включённым Full Level, см. ниже).

| Позиция | Пэд на корпусе | Банк A | Банк B |
|---|---|---|---|
| Верхний ряд, 1 | PAD5 | 52 (E3) | 65 (F4) |
| Верхний ряд, 2 | PAD6 | 53 (F3) | 67 (G4) |
| Верхний ряд, 3 | PAD7 | 55 (G3) | 69 (A4) |
| Верхний ряд, 4 | PAD8 | 57 (A3) | 71 (B4) |
| Нижний ряд, 1 | PAD1 | 45 (A2) | 59 (B3) |
| Нижний ряд, 2 | PAD2 | 47 (B2) | 60 (C4) |
| Нижний ряд, 3 | PAD3 | 48 (C3) | 62 (D4) |
| Нижний ряд, 4 | PAD4 | 50 (D3) | 64 (E4) |

В `firmware/mpk_mapping.h` массивы индексируются по номеру пэда на корпусе
(индекс = PADn − 1), а не по позиции в этой таблице.

## Крутилки K1–K8

- Канал **1**, CC **70–77** (K1=70 … K8=77, слева направо).
- Значения **абсолютные 0–127**, несмотря на то что сами энкодеры физически
  бесконечные (без упора). Подтверждено: CC71 дошёл ровно до 127 и держался
  там, у остальных крутилок значение доходило до 0 и там же оставалось.
- Практический вывод для стори **3.6** (чтобы параметр не прыгал при смене
  дорожки): раз это обычный абсолютный CC, а не relative-протокол,
  soft-catch-up логику всё равно придётся писать в прошивке — аппаратно эта
  проблема не решается.

## Джойстик

- Канал **1**.
- Ось **X** (влево/вправо) → **Pitch Bend**, диапазон **-8192…8191**.
- Ось **Y** (вверх/вниз) → **CC1** (mod wheel), диапазон **0–127**.
- Обе оси пружинят обратно в центр/0 при отпускании.

## Кнопки без собственного MIDI-сигнала

Ни одна из кнопок ниже не шлёт свой Note/CC при нажатии — все они локально
меняют поведение контроллера, и MIDI-эффект виден только в последующих
сообщениях от клавиш/пэдов (или не виден вообще). Проверено на живом
контроллере, не предположение.

- **Oct− / Oct+** — сдвигают номер ноты клавиш на **±12 полутонов за
  нажатие** (ровно одна октава, никаких прыжков на несколько сразу).
  Проверенный диапазон: от **12 (C0, −3 октавы)** до **108 (C8, +5 октав)** от
  базы — на обеих границах контроллер клипует и дальше не двигается. На самой
  нижней границе один раз поймали баг: пришёл `note_off note=0` без парного
  `note_on` — судя по всему, на границе диапазона note-on иногда не
  отправляется, а note-off при отпускании всё равно уходит. Прошивка должна
  переживать note-off без активной ноты, не падать и не уходить в underflow.
- **Full Level** — пока включена, velocity пэдов жёстко **зафиксирована на
  127** независимо от силы удара (проверено: без неё velocity гуляла от 1 до
  127, с ней — только 127).
- **Note Repeat** — работает **только на пэдах**, на клавишах эффекта нет
  (проверено отдельно: держали клавишу с включённым Note Repeat — ни одного
  повторного сообщения). Пока пэд зажат, ретриггерит note_on/note_off с
  фиксированным интервалом, привязанным к внутреннему темпу контроллера (см.
  ниже про темп).
- **Arp On/Off** — пока включён, генерирует автоматическую последовательность
  нот из зажатых/недавно зажатых клавиш с тем же внутренним темпом. Замечено:
  если нажимать новые клавиши, не отпуская или не выключая арп, паттерн может
  «копить» ноты и разрастаться — риск флуда потока нот, если оставить
  включённым во время реальной игры.
- **Tap Tempo** — **вообще не шлёт MIDI**: ни Note, ни CC, ни Pitch Bend, ни
  MIDI Clock/Start/Stop/Song Position, ни sysex (логгер их не игнорирует,
  проверяли специально). Темп меняется только внутри контроллера и виден
  только на его собственном экранчике. Подтверждено косвенно: после
  перетапывания с 191 на 72 BPM интервал ретриггера Note Repeat/Arp изменился
  — то есть внутренний темп реально меняется, просто наружу по MIDI никак не
  транслируется.
- **Bank A/B, CC, Prog Change, Prog Select** — тоже полностью локальные,
  никакого MIDI-сигнала при нажатии. Меняют, какую раскладку/PGM использовать
  дальше, но сам факт переключения прошивке не виден.

### Темп ретриггера ≈ сетка 16-х от внутреннего BPM

При BPM 191 на экране контроллера интервал между нотами при Arp/Note Repeat
составил стабильно **≈78 мс**. Для 16-й ноты это ожидаемо:
`60000 / (191 × 4) ≈ 78.5 мс` — сходится. То есть внутренний генератор
работает по сетке шестнадцатых относительно показанного BPM, просто эту сетку
не транслирует по MIDI.

## Важные выводы для прошивки

- **Тап-темпо на самом контроллере бесполезен для синхронизации секвенсора**
  (стори 1.4): либо реализовывать тап-темпо полностью на ESP32 по интервалам
  между живыми нотами/пэдами, либо не привязываться к внутреннему темпу MPK
  вообще. Риск из бэклога («[Вероятно] Tap Tempo не отправляет темп наружу»)
  подтверждён на живом железе, можно снимать пометку [Вероятно].
- **Номера нот пэдов зависят от активной PGM на контроллере.** Прошивка либо
  жёстко рассчитывает на эту конкретную PGM (и это нужно задокументировать как
  требование к железу при запуске), либо делает раскладку настраиваемой/через
  MIDI-learn — отдельная стори, не блокирует PoC.
- **Note Repeat и Arp могут флудить поток нот**, если их не выключить на
  контроллере перед игрой — для стори 3.1 (единый источник нот) самое простое
  решение на PoC: требовать, чтобы обе функции были выключены во время игры, а
  не обрабатывать их особо в прошивке.
- **Октава клипует, а не оборачивается**, и на границе возможен sole
  `note_off` без `note_on` — прошивка должна безопасно игнорировать такие
  сообщения.
- **Крутилки абсолютные (0–127), не relative** — защита от скачка параметра
  (3.6) реализуется только программно.

## Как переснять

Если PGM на контроллере поменяется (или раскладка станет подозрительной):

```
pip install -r tools/requirements.txt
python tools/midi_logger.py
```

Жать элементы по одному, сверяя вывод по времени. Скрипт печатает тип
сообщения, канал, номер и значение под каждое MIDI-сообщение в реальном
времени.
