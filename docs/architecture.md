# Текущая архитектура

Документ описывает архитектуру, которая есть в `current-state`. Это не проект будущего полноценного инструмента.

## Разделение выполнения

Код разделён по ответственности, а не по разделам интерфейса:

```text
core 1
  input task
       |
       v
  firmware.ino
  UI + application state
       |
       +--------------------+
       |                    |
       v                    v
  UiScreens             Transport API
                            |
                            v
core 0                 musical clock
  audio task                 |
       |                     v
       +--------------> AudioEngine
                             |
                             v
                        audio buffer
                             |
                             v
                        output adapter
```

Главное: отрисовка интерфейса и музыкальное время больше не живут в одном цикле.

## Ввод

`InputSource` задаёт модель событий уровня приложения.

Текущие типы событий:

- `NoteOn`;
- `NoteOff`;
- `ControlChange`;
- `KnobTurn`.

Текущая реализация — `WokwiInputSource`. Она читает симулированные сдвиговые регистры и энкодеры и превращает их в те же события приложения.

Будущий ввод по USB-MIDI должен заменить этот адаптер, не трогая секвенсор и звуковой движок.

## Слой приложения

`firmware/firmware.ino` — верхний слой приложения.

Сейчас он владеет:

- состоянием питания;
- текущим режимом интерфейса;
- состоянием меню;
- курсорами;
- настройками микшера;
- данными piano roll;
- выбором в аранжировке;
- отображением состояния экспорта;
- разбором событий ввода по модулям.

Он сознательно пока не разбит на множество контроллеров: это оркестрирующий слой PoC.

## Модель паттерна

`StepSequencer` сознательно маленький.

Сейчас:

- 4 дорожки;
- 16 шагов;
- 4 шага на такт;
- каждый шаг включён или выключен.

Он хранит только данные паттерна.

Музыкальные часы в этот класс не входят.

## Транспорт

`Transport` владеет живыми музыкальными часами.

Он:

- хранит BPM;
- отсчитывает время в выходных сэмплах;
- ведёт плейхед;
- решает, когда срабатывает шаг;
- запускает нужные голоса через `AudioEngine`;
- генерирует щелчки метронома;
- отдаёт интерфейсу снимок паттерна;
- отдаёт небольшую очередь сработавших шагов для интерфейса и лога.

`Transport` также реализует `AudioSource`, поэтому живой вывод запрашивает звук у того же объекта, который владеет музыкальным временем.

Время шага считается в сэмплах с накоплением остатка, чтобы целочисленное деление постепенно не сдвигало сетку.

## AudioEngine

`AudioEngine` владеет цепочкой:

```text
pending triggers
       ↓
voices
       ↓
per-voice gain
       ↓
integer mix accumulator
       ↓
master gain
       ↓
int16 limiting
       ↓
renderBlock()
```

Состоянием голосов владеет контекст рендера.

Вызовы со стороны управления — `trigger()`, `stopAll()` — публикуют отложенное состояние; рендер забирает его на границах блоков.

Движок не знает, куда уходит его выход.

Каждый экземпляр держит две таблицы щелчка метронома, рассчитанные на максимальную частоту вывода 48 кГц. Экземпляров два — живой и в экспортёре, — и вместе они занимают около трети статического DRAM ([known-issues, п. 6](known-issues.md#6-два-экземпляра-audioengine-занимают-треть-статического-dram)).

## Живой вывод

`OneBitAudioOutput` — реализация вывода для Wokwi.

Задача звука заполняет кольцевой буфер. Прерывание таймера только забирает готовые сэмплы и переключает симулированный GPIO.

То есть прерывание таймера не микширует звук.

Запаса кольцевого буфера — 256 сэмплов, 16 мс на 16 кГц — не хватит, чтобы пережить стирание страницы флеша: когда появится сохранение, это нужно учесть ([known-issues, п. 10](known-issues.md#10-запись-во-флеш-даст-паузу-в-звуке)).

На железе его планируется заменить выводом через I2S-кодек.

## Офлайн-экспорт

`PatternExporter` рендерит паттерн офлайн в WAV-поток.

Он использует собственный экземпляр `AudioEngine`, независимый от живого вывода. Поэтому экспорт детерминирован и не зависит от скорости симуляции Wokwi.

Текущий путь экспорта:

```text
pattern
   ↓
PatternExporter
   ↓
AudioEngine
   ↓
PCM WAV bytes
   ↓
base64/CRC framed Serial output
   ↓
Wokwi Serial Monitor
   ↓
export_bookmarklet.html
```

Такой экспорт — обходной путь для разработки в Wokwi, а не финальное хранение на устройстве.

## Интерфейс

`UiScreens` содержит общие примитивы отрисовки и основные экраны.

`ui_sections.cpp` содержит текущие разделы Mixer, Piano Roll и Arrangement.

Часто меняющиеся элементы перерисовываются частично, но полная смена экрана в Wokwi остаётся медленной.

Интерфейс не отвечает за музыкальное время.

## Текущие инварианты

Основные архитектурные правила, которые стоит сохранить:

1. Железо ввода спрятано за `InputSource`.
2. `StepSequencer` хранит данные паттерна, но не владеет временем транспорта.
3. Музыкальное время не зависит от отрисовки интерфейса.
4. `AudioEngine` не зависит от физического устройства вывода.
5. Прерывание таймера не рендерит звук.
6. Офлайн-экспорт рендерит звук по той же семантике, что и живой вывод.
7. Особенности Wokwi остаются в адаптерах и конфигурации.
