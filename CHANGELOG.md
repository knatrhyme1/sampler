# Changelog

Все заметные изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Проект пока не имеет версионных релизов (стадия PoC), поэтому все изменения
собраны в `[Unreleased]`; нумерация версий (semver) появится после первого
релиза PoC. Каждый пункт ссылается на стори из [`docs/backlog.md`](docs/backlog.md)
и короткий хеш коммита.

## [Unreleased]

### Added

- Экран переведён в альбомную ориентацию 320×240: `tft_.setRotation(1)` в
  `UiScreens::begin()` плюс `"rotate": 90` у детали `lcd1` в
  `firmware/diagram.json`, подтверждено визуально в симуляторе Wokwi —
  стори 9.0
- Экран загрузки переработан под анимацию из канваса "SMPLR Boot Screen" в
  Claude Design: растровый спрайт логотипа "SMPLR"
  (`firmware/logo_bitmap.h`, 1 бит/пиксель, сгенерирован новым инструментом
  `tools/png_to_bitmap.py` из `smplr-logo.png`), процедурный глитч поверх
  него (сдвинутые полосы-слайсы + цветные пиксели-конфетти короткими
  вспышками), прогресс-бар из 20 блоков и статус-текст с реальным процентом
  готовности — управляется прошивкой (`UiScreens::showBoot(uint8_t percent)`),
  не запись видео/gif. Точные цвета, позиции и тайминги — из исходника
  канваса `boot-scene.jsx` — стори 9.0
- `tools/png_to_bitmap.py`, `tools/bitmap_preview.py` — конвертация PNG в
  1-битный PROGMEM-массив для `Adafruit_GFX::drawBitmap`-подобной отрисовки
  и обратный рендер массива в PNG для проверки без прошивки/симулятора —
  вспомогательные инструменты к стори 9.0
- `firmware/input_source.h` — общий интерфейс `InputSource` (NoteOn/NoteOff/CC),
  не зависящий от того, откуда приходят события — стори 3.1
- `firmware/wokwi_input_source.cpp/h` — `WokwiInputSource`: чтение пэдов и
  клавиш через цепочку из пяти 74HC165 и 8 крутилок через ADC в симуляции
  Wokwi — стори 3.1, частично 3.4 (без джойстика)
- Экраны включения / загрузки / приветствия на ILI9341
  (`firmware/ui_screens.cpp/h`, интеграция в `firmware/firmware.ino` через
  кнопку POWER с защитой от случайного нажатия) по брифу
  [`docs/boot-screen-brief.md`](docs/boot-screen-brief.md) — стори 9.0 (новая,
  вне исходного скоупа PoC)
- `firmware/diagram.json` дополнен экраном ILI9341, кнопкой POWER, пятью
  74HC165 и восемью потенциометрами для симуляции полного набора физических
  элементов ввода в Wokwi
- `docs/known-issues.md` — журнал открытых багов и не до конца проверенного
  поведения, отдельно от бэклога стори
- Раскладка Akai MPK mini под PoC-скоуп: клавиши, пэды, крутилки, джойстик —
  стори 3.2 (`ca461a9`)
- Прошивка-заглушка (heartbeat) для ESP32-S3, симулируемая в Wokwi —
  стори 0.2 (`b986ef1`)
- Звуковой движок: рендер тестового тона 440 Гц в WAV-файл —
  стори 0.3 (`b986ef1`)
- Бэклог по эпикам и сториям, README проекта — стори 0.1 (`b986ef1`)
- `tools/midi_logger.py` — разовый инструмент для снятия реальной MIDI-раскладки
  с подключённого контроллера — стори 3.2 (`a26534c`)
- `firmware/mpk_mapping.h` — константы раскладки MPK mini для будущего
  MIDI-парсинга прошивки (стори 3.3/3.4) — стори 3.2 (`a26534c`)

### Changed

- `UiScreens::showBoot()` принимает реальный процент готовности (0..100)
  вместо номера фиксированного шага из списка — прогресс, статус-текст и
  прогресс-бар отражают то, что передаёт вызывающий код, а не заранее
  запечённую последовательность кадров; `firmware.ino::updateBoot()`
  считает процент от реального прошедшего времени (`BOOT_DURATION_MS`) и
  перерисовывает не чаще `BOOT_FRAME_MS`, чтобы не перегружать
  симулируемый SPI — стори 9.0
- Раскладка Akai MPK mini в `docs/mpk-mapping.md` переснята с реального
  контроллера вместо предположений по общим знаниям об устройстве: точные
  номера нот/CC по каждому элементу, поведение кнопок без собственного
  MIDI-сигнала (Oct+/-, Full Level, Note Repeat, Arp On/Off, Tap Tempo, Bank
  A/B и меню PGM), подтверждённый риск по Tap Tempo (не транслирует темп по
  MIDI) — стори 3.2 (`a26534c`)

### Fixed

- Прошивка доходит до первого `heartbeat` и штатно проходит состояния
  Off/Boot/Home за разумное время в симуляции Wokwi — ранее подозревался
  медленный софтверный SPI при `fillScreen()` на ILI9341, на практике
  экраны включения/загрузки/приветствия подтверждены визуально
- Отладочные `Serial.print` с префиксом `dbg:` убраны из
  `firmware.ino::updateBoot()` вместе с переходом на процент-based прогресс
- Конфигурация симуляции прошивки для `wokwi-cli`: `wokwi.toml` указывает на
  смёрженный образ и ELF из сборки `arduino-cli`, серийный порт платы
  подключён к `$serialMonitor` в `diagram.json` — стори 0.2 (`1f0d6f0`)

### Known Issues

Открытые проблемы без исправления пока не удаляются из `Added`/`Changed` —
подробности и статус в [`docs/known-issues.md`](docs/known-issues.md).

- Растровый спрайт логотипа "SMPLR" на экране загрузки
  (`firmware/logo_bitmap.h`, отрисовка через `UiScreens::drawLogoRows()`)
  отображается в симуляторе Wokwi битым/переставленным местами вместо
  цельного читаемого слова. Данные битмапа и алгоритм распаковки бит
  проверены и исключены как причина; рабочая гипотеза — разрыв кадра
  (tearing) из-за большого числа мелких `drawFastHLine()`-транзакций на
  хатч-текстуре, либо баг адресации при `setRotation(1)` в паре с
  симулятором чипа `wokwi-ili9341` — не подтверждено. Подробности, что уже
  исключено и промт для отдельной сессии — в
  [`docs/known-issues.md`](docs/known-issues.md), раздел 1.
